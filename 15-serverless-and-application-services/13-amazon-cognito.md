# Amazon Cognito

- AC provides Authentication, Authorization and User Management for applications.
- There are two main components of Amazon Cognito:
  - **User Pools**: User directories that provide sign-up and sign-in options (e.g MFA, SSO) for your app users.
  - **Identity Pools**: Provide temporary AWS credentials to access AWS services.
- Note: **User Pools** identities are not AWS identities, they cannot access AWS resources.
- **Identity Pools** can used to swap external identities or **User Pools** identities for short term AWS credentials. This is called **federated identities**.
- **Identity Pools** use IAM role to grant identities permissions.

## User Pools Architecture

1. An application calls to Cognito User Pools for authentication.
2. User Pools return a JWT token.
3. JWT can be used by the application to access the application resources or used by AWS API Gateway to access AWS Lambda (or other backend resources supported by API Gateway).

- JWT generated by Cognito is not an AWS credential, it cannot be used to access AWS resource.

## Identity Pools Architecture

1. An application calls to an identity provider (e.g. google).
2. The identity provider return a JWT token.
3. The application passes the JWT token to Cognito Identity Pools.
4. Cognito Identity Pools swaps the JWT token for AWS credentials by assuming a role.
5. The AWS Credentials are passed back to the application to access AWS resources.

- Each identity provider must have a dedicated set of configurations in Cognito Identity Pools.
- At least 2 types of roles needs to be configured: 1 for authenticated identities and 1 for unauthenticated identities.
- Once the AWS credentials expire, the application must renew them.

## Using User Pools with Identity Pools

- Problem: The downside of using Identity Pools alone is that your application needs to handle multiple identity providers.
- By using User Pools with Identity Pools, you can delegate the logic to handle multiple identity providers to User Pools. Your application only needs to care about 1 identity provider - The Cognito User Pools.

1. An application calls to Cognito User Pools for authentication.
2. User Pools return a JWT token.
3. The application passes the JWT token to Cognito Identity Pools.
4. Cognito Identity Pools swaps the JWT token for AWS credentials by assuming a role.
5. The AWS Credentials are passed back to the application to access AWS resources.
