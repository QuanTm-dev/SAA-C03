# ACM (AWS Certificate Manager)

## HTTP and HTTPS (No Anki Cards needed)

- HTTP is simple but insecure
- HTTPS uses SSL/TLS to add an encryption layer to HTTP
- Data is encrypted in transit

## Certificates and trust (No Anki Cards needed)

- SSL/TLS lets servers prove their identity using certificates
- A certificate can be signed by any one CA that the client trusts

## Certificate types

- ACM works with both public and private CAs

### Public certificates

- Issued and signed by Amazon Trust Services (ATS)
- ATS is a publicly trusted CA

### Private certificates

- Issued and signed by AWS Private CA
- Clients must trust your private CA root

## Certificate lifecycle

### Generated by ACM

- ACM can generate certificates
- ACM can automatically renew certificates it generated

### Imported

- ACM can import certificates
- You are responsible for renewing imported certificates

## Deployment

- A certificate must be attached (deployed) to an AWS resource to take effect
- Certificates can be directly attached only to supported AWS-integrated services. EC2 is not supported by ACM
- Exportable public certificates can be installed on resources outside integrated services

## Regional scope

- ACM is a regional service
- Certificates can't be copied to another region or used by resources there. Exportable certificates are an exception.
- An AWS service that uses an ACM cert needs to be in the same region as the cert
- CloudFront can only use `us-east-1` certs (Because global services are treated as they run on `us-east-1`).
